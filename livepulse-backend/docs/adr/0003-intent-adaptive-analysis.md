# ADR-0003：意图自适应分析（按主播类型评估，不把带货标准套到教学主播头上）

**状态**：原则已接受。AI 复盘 v2 = 第一个实例（已 ship）；评分 + 主分析面板 = M2（需 anchor.type）
**日期**：2026-06-03
**决策者**：owner + claude（AI 复盘输出质量复盘时产出）

---

## 背景

2026-06-03 优化 AI 复盘时，owner 指出一个被整个产品默认掉的偏见：
**默认所有主播都以"带货转化"为目标。**

但现实：很多主播是**纯教学型**（如 demo 里的"教化妆的阿野""小鱼儿教化妆"），
为保口碑几乎不带货。对他们用转化标准评估 = **反而有害的错误建议**。

这是产品价值观问题：教练应该帮主播把【他自己想做的事】做得更好，
不是逼所有人去卖货。

## 决策

**任何分析在评估前，必须先确定主播类型，并按【该类型自己的目标】评估。**

| 类型 | 目标 | 评估重点 |
|------|------|---------|
| 教学型 | 教清楚、可跟随、涨粉、留存、口碑 | 教学结构/清晰度、互动捕获、涨粉钩子 |
| 带货型 | 转化 | 产品桥接、逼单、痛点→产品 |
| 互动陪伴型 | 黏性、停留 | 互动密度、情绪、福利节奏 |
| 混合型 | 教学+带货 | 两者按时段切换评估 |

**铁律**：教学型/不带货主播，**禁止**建议带货、逼单、接产品。

## 实例进度

### ✅ 已 ship：AI 复盘 v2（PROMPT_VERSION v2）
prompt 让模型**每次现场推断**主播类型（从主播名/标题/内容），按其目标产出 findings。
教学型不给带货建议。详见 [[project-ai-range-analysis-v2]]。

### 🔴 M2：主分析页 + 评分（重灾区，比 AI 复盘影响更大）
主分析页的转化分析是 **pipeline 阶段算好存 DB 的**，无"现场推断"机会，
**前提是 `anchor.type` 字段**（主播建档时声明）。有了它，M2 要做：

1. **评分自适应**：composite 现在 = 内容×0.4 + 互动×0.3 + **转化×0.3**。
   教学型主播不带货 → 转化分天然低 → **综合分被不公平拉低**。
   教学型应不计/降权转化（如 内容×0.6 + 互动×0.4）。
2. **面板自适应**：教学型隐藏「购买意向漏斗」「最容易触发购买的话术」「强购买占比」，
   换成教学向分析（教学清晰度 / 涨粉留存）。
3. **核心问题卡**：不对教学主播喊"强购买占比 0%"（= 说他卖货失败，但他没在卖）。

## 为什么 M1 不做主分析页自适应

没有 `anchor.type` 字段，硬做就是逐栏 if-else（与 ADR-0002 反对的"逐域局部补丁"同构）。
正确做法：M2 先加字段，再让评分公式 + 面板 + 核心问题卡统一按字段分支。
M1 期间：AI 复盘 v2 现场推断已覆盖最高价值入口；主分析页的转化偏见**已知、容忍、记 M2**。
