# 用户流程设计

> 核心原则：**"上传即开工"** — 用户上传视频后立刻能干活，分析在后台跑。
>
> 永远不让用户对着进度条干等。

---

## 2. "上传即开工" 详细时间线（30 分钟录屏，4G 网络）

| 时间 | 用户看到 | 后台在做 |
|---|---|---|
| **00:00** | 点"选视频"按 PHPicker | - |
| **00:05** | 视频已加载，**进入工作台** | 后台 4 件事开跑 |
| **00:05** | 视频可播、可拖拽、可记笔记 | 端侧 ASR / 抽帧 / 转码 / 上传开始 |
| **00:30** | "已发现 3 个可能亮点 🔥"（卡片） | 端侧粗识别完成 |
| **00:30** | 用户开始记第一条笔记 | - |
| **00:45** | 话术区出现："01:20-01:35 已识别 [话术片段]" | 端侧 ASR 出第一段 |
| **01:30** | 话术全部出现，标题"识别完成 ✓" | 端侧 ASR 完成 |
| **02:00** | 进度条提示"上传 60%" | 转码 + 上传进行中 |
| **02:30** | 进度条："上传完成 · AI 分析中" | server 收到，跑 OCR + 分析 |
| **02:30** | 用户**可以关闭 app** 干别的 | server 继续跑 |
| **05:00** | 🔔 推送："复盘报告就绪 · 综合分 75" | server 完成所有分析 |
| **05:01** | 用户点通知 → 跳报告页 | - |
| **05:02** | 用户切到"高光切片" tab | 端侧已有亮点候选 + server 精准识别合并 |
| **05:05** | 选 3 个亮点 → 一键发布抖音 | OpenSDK 调起官方分享 |

**关键观察**：
- 用户在 **00:05 - 05:00 之间永远在工作**，从未对着进度条干等
- 服务端分析在用户工作的同时跑完
- 推送通知是 fallback（用户关 app 也能用）

### 3.2 各 Tab 的"待状态"设计

| Tab | 立即可用 | 占位文案（数据未到时） |
|---|---|---|
| **笔记** | ✅ 立即（本地） | - |
| **话术** | ⏳ 渐进式 | "正在识别 30%... 已识别 [可见部分]" |
| **洞察** | ⏳ 等服务端 | "AI 正在分析这场直播... 完成后会通知你" + 骨架屏 |
| **切片** | ⏳ 半立即 | "端侧识别到 3 个候选亮点 · 服务端精准识别中" |

### 3.3 笔记功能（"上传即开工"的核心）

**MVP 功能**：
- 在当前播放时间点记笔记（按"+"按钮自动绑定 timestamp）
- 笔记列表按时间轴排序
- 点击笔记 → 视频自动跳转到该时间点
- **富文本（Markdown 存储 + `AttributedString` 渲染）**
- 笔记本地存（SwiftData） + 后台 sync 到 server
- 离线可用，有网时自动 sync

### 富文本编辑器交互（极简版，不做 WYSIWYG）

```
┌────────────────────────────────────────┐
│ 02:35 这段逼单效果不错,下次可以学      │
│ ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━     │
│                                         │
│ [B] [I] [H] [@02:35]                    │  ← 工具栏固定在键盘上方
└────────────────────────────────────────┘
```

- **[B 加粗]**：选中文本 → 包 `**xxx**`
- **[I 斜体]**：选中文本 → 包 `*xxx*`
- **[H 高亮]**：选中文本 → 包 `==xxx==`
- **[@时间锚]**：当前播放时间 → 插入 `[02:35]`（点击可跳转）

显示时全部用 `AttributedString(markdown:)` 渲染。

**M3 候选**：
- @ 引用 AI 洞察（"AI 说我开场太短了，确实"自动链接）
- 笔记导出 PDF / 分享卡片

## 4. 端侧 ASR 显示策略

### 渐进式显示

```
00:00  「正在识别...」
00:30  「正在识别 20% · 已识别前 6 分钟」
       ↓ 已识别部分点击可跳转
       [01:20] 大家好今天给大家介绍...
       [02:35] 这款口红是国货精品...

01:00  「正在识别 60% · 已识别前 18 分钟」
       ↓ 新增部分
       [10:15] 现在我们来看下一款...

01:30  「识别完成 ✓ · 共 X 段话术」
       ↓ 全部显示
```

### 端侧 vs 服务端 ASR 协调

- 端侧 ASR（Apple Speech Framework）：**快**（2-3 分钟跑完 30 分钟视频），免费，离线
- 服务端 ASR（阿里云）：**准**（专业词识别更好），但要等上传完成 + 跑 ~2 分钟

**策略**：
1. 端侧 ASR 结果先显示（用户立刻能看）
2. 服务端 ASR 完成后**自动 diff + 替换**差异部分（用户可能感知不到，因为大部分都准）
3. 关键差异（如品牌名、产品名）显示一个小 ⓘ 提示"已更精准"

## 4.5 端侧预处理 — 缩短分析时间（2026-06-09 讨论固化）

> 核心问题（owner 提出）：能不能用手机本身算力先预处理视频，缩短整体分析时间？
> 答案：能，且是对的方向。但要区分清楚**两种不同的收益来源**。
>
> ⚠️ **2026-06-10 更新**：「① 端侧转码压缩」**已拍板不做**——手机录屏竖屏 888×1920
> 压缩会废 OCR 小字（核心价值），实证原画 OCR 正常出分。详见
> [03-roadmap.md Sprint 3 转码决策](03-roadmap.md)。下方「② 端侧 ASR」不受影响，仍是 M3 候选。

### 两种收益，分开看

| 收益 | 做法 | 量级 |
|---|---|---|
| **① 缩短上传时间**（最大） | 手机先转码压缩再上传 | 上传 13-20min → 2-3min |
| **② 缩短后端分析时间** | 端侧 ASR → 后端跳过自己的 ASR | 后端省 2-3min |

### ① 端侧转码压缩（收益最大）

- HEVC → H.264、1080p → 720p、降码率
- 用 **VideoToolbox 硬件编码**（苹果亲儿子，1-2 分钟跑完 30 分钟视频）
- 上传体积 **1.5GB → ~200MB** → 4G 上传从 13-20min 降到 2-3min
- **移动网络上传慢是最大时间杀手**，这一步收益最高
- 配合「边转边传」（转完一段 chunk 立刻传），转码和上传时间重叠

### ② 端侧 ASR（缩短后端分析）

- 手机用 **Apple Speech Framework**（离线、免费、走神经引擎）做语音转文字
- 转完把文字稿随视频一起传给后端
- 后端 ASR 步骤改成「检测到端侧文字稿就跳过」→ 省阿里云 ASR ~2-3min
- 详见 [04-backend-changes.md](04-backend-changes.md) 的「端侧 ASR 回传」(P1)

### 哪些能搬到端侧 / 哪些必须留后端

| 步骤 | 端侧能做？ | 说明 |
|---|---|---|
| 转码压缩 | ✅ 强烈推荐 | VideoToolbox 硬件编码，最大收益 |
| 语音转文字 ASR | ✅ 推荐 | Apple Speech，省后端 ASR |
| 抽帧 | ✅ 能 | AVAssetImageGenerator |
| **OCR（弹幕/在线人数）** | ⚠️ 不建议 | 端侧 Vision 对中文小字/弹幕准确率🤔不如阿里云，留后端 |
| 高光粗识别 | ✅ 能 | 音量峰值 + 帧差异，给即时反馈 |
| 评分 / 洞察 / AI 分析 | ❌ 留后端 | 要调 LLM + 复杂逻辑 |

### 整体时间对比（30 分钟录屏，4G）🤔 估算

| 阶段 | 现状（web） | 端侧预处理后 |
|---|---|---|
| 上传 | 13-20 分钟 | 转码 1.5min + 边转边传 |
| 后端分析 | 3-5 分钟 | 无 ASR → 2-3 分钟 |
| **总等待** | **17-26 分钟** 🔴 | **5-6 分钟** ✅ |

配合「上传即开工」，用户感知等待几乎为 0（边记笔记边后台跑）。

### 代价（诚实记录）

- 端侧转码耗时 1-2min + 发热 + 耗电（但跟上传重叠，净省时间）
- 端侧 ASR 准确率：一般用语 90%+，美妆专业词/品牌名🤔可能不如阿里云
  → 策略：端侧出"快速版"先显示，后端 ASR 回来再"精准版"覆盖（见 §4 策略）
- 增加 app 端复杂度（转码状态机、后台任务、错误处理）

### 🔴 前置依赖（这是 Sprint 3 的工作）

端侧预处理优化属于 **Sprint 3（上传）**，前提：
1. 后端先做 **chunked upload endpoint**（[04-backend-changes.md](04-backend-changes.md) P0）
2. 后端 ASR 步骤改成「有端侧文字稿就跳过」
3. iOS 端做转码（AVAssetExportSession + VideoToolbox）+ 端侧 ASR + 边转边传

**当前 app 还没做"真正上传到后端"**（选视频只进本地工作台），所以这个优化的前置是 Sprint 3。先把浏览/笔记/工作台核心做稳，上传是下一个大块。

## 5. 高光切片端侧/服务端结果合并策略

### 时序

| 时间 | 来源 | 候选数 | 用户可操作 |
|---|---|---|---|
| 00:30 | 端侧粗识别（音量峰值 + 帧差异 + 端侧 ASR 情绪词） | 3 个 | ✅ 立即可预览、可"加入切片" |
| 05:00 | 服务端精准识别（OCR + 评分 + insight） | 5-7 个 | ✅ 替换/补充端侧结果 |

### 合并规则（避免"我刚选的怎么没了"焦虑）

```
对每个端侧候选 X：
  如果服务端候选有跟 X 时间重叠的 Y：
    → 用 Y 替换 X（服务端区间更精准），保留用户对 X 的操作（已加入切片状态继承）
  否则：
    如果用户已对 X 操作（点过"加入切片"）：
      → 保留 X，标"用户选择"
    否则：
      → 标灰 + 提示"AI 评估优先级较低"，用户可手动恢复

对每个服务端独有候选 Z（端侧没有的）：
  → 追加到列表末尾，标"AI 推荐"
```

## 6. 推送通知设计

### 通知触发点

| 触发 | 通知内容 | 点击行为 |
|---|---|---|
| 端侧 ASR 完成（如果用户已退出 app） | 「话术识别完成，可以复盘了」 | 跳工作台 |
| 服务端早期洞察 B5 完成 | 「Top3 改进点已就绪」 | 跳报告页 |
| 服务端完整分析完成 | 「复盘报告就绪 · 综合分 75」 | 跳报告页 |
| 切片发布完成（用户在抖音操作期间） | 「切片已发布到抖音」 | 跳抖音 app |

### 通知内容模板

不用通用模板「分析完成」—— 用**具体数字**触发好奇心：
- ✅ "你这场综合分 **75** · 比上场高 8 分"
- ✅ "互动分 60，转化分 80 · 看看为什么"
- ❌ "你的直播分析已完成"（太干）

## 7. 离线场景

| 场景 | 处理 |
|---|---|
| 用户没网时打开 app | 进入"历史场次"，看本地缓存过的报告 |
| 用户没网时选了视频要上传 | 进入工作台，端侧 ASR + 笔记完全可用；上传任务进队列，有网时自动开始 |
| 用户记笔记时断网 | 笔记本地存，恢复网络时自动 sync |

---

## 8. 错误场景

| 场景 | 处理 |
|---|---|
| 视频格式不支持 | 选完立刻提示，不让进工作台 |
| 视频时长 < 1 分钟 | 提示"分析需要至少 1 分钟视频"（短视频信号不够） |
| 上传中断（网络问题） | 显示"已暂停 · 网络恢复后继续"，不要重传整个 |
| 服务端分析失败 | 推送"分析失败 · 点击重试"；保留用户的本地笔记 |
| 端侧 ASR 失败（极少见） | 静默降级，话术 tab 显示"识别异常 · 等服务端识别" |
