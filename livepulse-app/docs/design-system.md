# LivePulse Design System（v1 · 当前系统）

> 本文从**现有 iOS 代码**（`DesignSystem/Theme.swift` + 8 个界面）归纳，不是泛泛 UI 总结。
> 目标：给设计师 + 前端一份可直接照着做的 SSOT，并修掉当前的不一致。
> ⚠️ 范围：codify **当前浅色 + 紫色系统**。深色霓虹重构是独立的 v2 提案，不在本文。
> 信源：色值/圆角/间距 = ✅ 从代码直接抽取；命名分级与"建议补充项" = 🤔 我的归纳。

## 0. 设计语言（灵魂）

> 比 token 更上一层 —— 这个 app 的**性格和信念**，回答"什么让 LivePulse 看起来像 LivePulse"。
> 下面的规则（§3 起）都是这套语言的落地。

**一句话**：**「安静的教练」** —— 干净、克制、可信，把复杂的直播数据收拢成一个主播单手就能读懂、读完知道下一步做什么的界面。

**性格（四个词）**
- **克制 Restrained** —— 单一紫色、大量留白、几乎无装饰；信息靠层级和间距区隔，不靠线条色块。
- **可信 Trustworthy** —— 数据如实呈现，缺失就留白，绝不浮夸编造；中性灰阶 + 朴素白卡，像一份认真的报告。
- **鼓励 Encouraging** —— 教练口吻；空态给下一步，不羞辱、不报红脸。
- **聚焦 Focused** —— 每屏一个主操作、单列竖屏，为碎片时间和单手而设计。

**核心信念（驱动每个决策）**
1. 清晰 > 装饰　2. 一屏一个主操作　3. 数据诚实 > 界面好看　4. 单主色纪律（紫色品牌 / 绿橙红只服务分数）　5. 鼓励而非评判。

**标志性视觉（一眼认出是 LivePulse）**
- 紫色作点睛、不作铺底　· 白卡 + 细边、不用阴影　· 分数即颜色　· 首字母圆形头像　· SF Symbols 统一图标语言　· 8pt 呼吸感留白。

**它不是什么（反面定义）**
- ❌ 炫技数据仪表盘（不堆图表、不撞色）　❌ 花哨消费 app（无彩色插画、无多品牌色、无重渐变）　❌ 冷冰冰后台工具（不羞辱、不抛报错代码）　❌ 不追求信息密度（宁可少而清）。

> 走暗场霓虹 v2 时，这套"性格/信念/声音"基本不变，变的只是"标志性视觉"那一层（深色 + 霓虹 + 辉光）。

## 0.5 产品功能地图（设计要服务的场景）

> 设计规范服务于这些真实功能。导航主干：登录 → 主播列表(主页) → 场次表 → 复盘工作台。

| 模块 | 功能 | 关键界面 |
|---|---|---|
| **账号** | 登录 / 注册（邀请码制） | LoginView / RegisterView |
| **主播列表（主页）** | 拉后端主播、按最近场次排序、入口上传 | AnchorListView |
| **上传** | 选录屏（PHPicker）→ 分块上传（断点续传/重试）→ 后端分析 | VideoPickerView |
| **场次分析表** | 每场综合分 + 互动/转化/内容三分 + 时长/日期/状态 | AnchorSessionsView |
| **跨场进步趋势**（差异化武器） | 综合分+三分跨场折线，看"自己在进步" | TrendView（Swift Charts） |
| **复盘工作台** | 播放器 + 时间轴 + 4 tab 容器 | VideoWorkspaceView |
| └ 笔记 | 时间锚 + 收藏 + Markdown + 后端同步备份 | NotesTab |
| └ 话术 | 字幕跟读高亮 + **AI 选段点评 + 历史**（差异化武器） | TranscriptTab |
| └ 洞察 | AI 报告（综合分 + 三分 + 洞察）+ 点洞察跳转视频 | InsightsTab |
| └ 高光时刻 | AI 高光列表（score≥60）+ 后端切片导出 → 分享 sheet（转剪映/存相册） | HighlightsTab |

**两大差异化武器**（设计应突出、不被淹没）：**AI 选段点评** + **跨场进步追踪**。
**核心承诺**："别再熬夜看回放，复盘只要 10 分钟" + "哪段该改、下一步怎么做"。

**对设计的含义**：
- 列表/卡片是主体语言（主播、场次、洞察、高光都是卡片流）。
- "分数"是反复出现的核心元素 → 评分配色 + 评分组件必须统一（见 §4.4 / §8.5）。
- 工作台是信息最密的地方（4 tab + 播放器）→ tab 一致性、状态统一最关键。
- 导出/上传/登录各是一屏的主操作 → 主按钮规范要硬性统一（见 §11.1）。

## 1. 产品气质 / 用户 / 场景

| 维度 | 判断 | 依据 |
|---|---|---|
| **产品气质** | 专业但亲和的"教练" —— 干净、克制、数据可信、鼓励向上 | 文案"别再熬夜看回放""让主播看到自己在进步"；紫色单主色；大量留白 |
| **目标用户** | 小主播 / 小 MCN owner，非技术、手机端、碎片时间 | iOS 单手操作、竖屏、列表+卡片为主 |
| **核心场景** | 手机上 10 分钟快速复盘一场直播：看分 → 看哪段该改 → 记笔记 → 导高光 | 工作台 4 tab、场次表评分、高光导出 |
| **气质关键词** | 清晰 > 炫技；引导 > 堆数据；鼓励 > 评判 | ADR-0003 按主播类型评估、空态给"下一步"而非冷冰冰报错 |

**对设计的约束**：信息密度要低（单手扫读）、每屏一个主操作、负向数据不羞辱用户、数据要"可信不浮夸"。

## 2. 视觉语言提炼（当前真实值）

- **色彩**：单主色紫 `#6366F1`；中性灰阶 4 级文字 + 3 级背景；评分语义三色（绿/橙/红）。
- **字体**：系统字体（SF/苹方），无自定义字体；**无正式字号阶梯**（见不一致 §11）。
- **间距**：4 / 8 / 16 / 24 / 32 的 8pt 体系（`LPSpacing`）。
- **圆角**：6 / 8 / 12 / 16（`LPRadius`），实际几乎只用了 8。
- **阴影**：**当前没有**。卡片靠 1px 边框 `#E5E5E5` 区隔 —— 扁平、边框驱动。
- **组件**：白卡 + 细边 + 圆角 8；胶囊标签；首字母圆形头像；SF Symbols 图标。
- **交互态**：禁用 = 透明度 0.5；加载 = ProgressView + "…中"文案；tab 选中 = 紫字 + 2px 下划线；列表下拉刷新。

## 3. 设计原则

1. **清晰优先于装饰** — 能用留白和层级解决的，不靠线条和色块。
   - ✅ 适用：所有列表、表单、数据展示。
   - 🚫 不要：为了"丰富"加分隔线、背景纹理、多余图标。

2. **每屏一个主操作** — 一个高对比主按钮，其余降级为次级/文字按钮。
   - ✅ 适用：登录（登录）、上传（选视频）、高光（导出）。
   - 🚫 不要：一屏出现两个同等权重的紫色实心按钮。

3. **数据可信不浮夸** — 分数、趋势如实呈现，缺失就降级为空，绝不编造（呼应产品守则 9.2）。
   - ✅ 适用：评分、趋势、高光、洞察。
   - 🚫 不要：0 数据时硬算百分比、空场硬塞"高光"。

4. **教练口吻** — 鼓励、给下一步，不评判。
   - ✅ 适用：空态、错误、引导文案。
   - 🚫 不要：用"失败/错误/无效"当面孔；负向洞察用羞辱式措辞。

5. **单主色纪律** — 紫色 `#6366F1` 是唯一品牌色，语义色（绿橙红）只用于评分。
   - ✅ 适用：主按钮、链接、选中态、强调。
   - 🚫 不要：引入第二个品牌色；用评分绿/红做装饰或按钮。

## 4. 色彩系统

### 4.1 品牌色

| Token | Hex | 适用场景 | 不要怎么用 |
|---|---|---|---|
| `accent` | `#6366F1` | 主按钮、链接、选中态、强调文字、头像字 | 🚫 大面积铺底（只做点睛）；🚫 与评分色混用 |
| `accentHover` | `#4F46E5` | 按钮按下/hover 态 | 🚫 当默认态 |
| `accentSoft` | `#EEF2FF` | 主色浅底：标签底、头像底、选中行底 | 🚫 当卡片主底（卡片是纯白） |
| `accentText` | `#4338CA` | 浅紫底上的深紫文字（头像首字母） | 🚫 当正文色 |

### 4.2 中性 / 文字

| Token | Hex | 适用场景 | 不要怎么用 |
|---|---|---|---|
| `text` | `#0A0A0A` | 标题、主要正文 | 🚫 当按钮底色（见不一致 §11.1） |
| `textMid` | `#525252` | 次级文字、表单 label | 🚫 当主标题 |
| `textMute` | `#A3A3A3` | 元信息、占位说明、空态正文 | 🚫 当可点击文字 |
| `textFaint` | `#C4C4C4` | 空态图标、无数据占位、chevron | 🚫 当任何需要可读的文字 |

### 4.3 背景 / 容器

| Token | Hex | 适用场景 | 不要怎么用 |
|---|---|---|---|
| `bg` | `#FAFAFA` | 页面底 | 🚫 当卡片底 |
| `bgSoft` | `#F0F0F0` | 进度条轨道、次级填充 | 🚫 当页面底（对比不足） |
| `card` | `#FFFFFF` | 所有卡片、表单输入框 | 🚫 直接贴在 `card` 上再放 `card`（无层次） |
| `border` | `#E5E5E5` | 卡片/输入框 1px 描边 | 🚫 当分隔线滥用 |

### 4.4 评分语义色（仅用于分数）

| Token | Hex | 阈值 | Soft 底（标签用） |
|---|---|---|---|
| `scoreHigh` | `#16A34A` | ≥ 75 | `scoreHighSoft #F0FDF4` |
| `scoreMid` | `#F59E0B` | 60–74 | `scoreMidSoft #FFF7ED` |
| `scoreLow` | `#EF4444` | < 60 | — |
| 无数据 | = `textFaint` | 未分析 / null | — |

- ✅ 适用：综合分、三分、趋势线、高光分数。**全 app 用同一套阈值**（修 §11.2）。
- 🚫 不要：把评分色用于非评分元素；高光分数写死橙色不分档（修 §11.9）。
- 三分标签配色（归纳自现有局部代码，提升为 token）：互动→`accentSoft`、转化→`scoreMidSoft`、内容→`scoreHighSoft`。

## 5. 字体系统

系统字体（iOS = SF Pro / 苹方），不引入自定义字体。下表是**建议的命名阶梯**（🤔 归纳 + 补齐），把现有散落的字号统一：

| 名称 | 规格 | 适用场景 | 不要怎么用 |
|---|---|---|---|
| `display` | 44 / Bold | 综合分巨数字（仅评分 hero） | 🚫 当标题；一屏 ≤1 处 |
| `title-l` | 28 / Bold | 页面级欢迎语（登录头） | 🚫 当卡片标题 |
| `title-m` | 22 / Bold（`.title2`） | 场次行综合分 | 🚫 当正文 |
| `headline` | 17 / Semibold（`.headline`） | 区块标题、空态主文案 | 🚫 当元信息 |
| `body-strong` | 15 / Semibold（`.subheadline` semibold） | 卡片标题、列表项标题 | — |
| `body` | 15 / Regular（`.subheadline`） | 正文、说明 | — |
| `caption` | 12 / Regular（`.caption`） | 元信息、标签、时间 | 🚫 当正文长段 |
| `micro` | 10–11 / Medium | 分数下注脚、密集标签 | 🚫 当主要信息；可读性边界 |

- ✅ 优先用语义字体（`.subheadline`/`.caption`，支持动态字体）。
- 🚫 不要：继续散用 `size: 10/11/28/44` 这类裸数字（现状混乱，见 §11.5）；同类元信息混用 caption/caption2/footnote。

## 6. 间距与栅格

8pt 体系（`LPSpacing`）：

| Token | 值 | 适用场景 | 不要怎么用 |
|---|---|---|---|
| `xs` | 4 | 图标与文字、标签内垂直 | 🚫 当卡片间距 |
| `sm` | 8 | 紧凑元素间、卡片内行距 | — |
| `md` | 16 | **卡片内边距标准值**、屏边距、卡片间距 | 🚫 列表项之间用比 md 更大的随意值 |
| `lg` | 24 | 区块之间、表单组间距 | — |
| `xl` | 32 | 屏内大分区、页眉上方 | 🚫 当常规间距 |

- **栅格**：单列为主（手机竖屏）；屏左右边距统一 `md(16)`；卡片间距 `10–16`（建议统一 `12`）。
- 🚫 不要：卡片内边距继续在 12 / 14 / 16 之间乱跳（见 §11.4）——**统一 16，密集列表 12**。

## 7. 圆角、边框、阴影

### 圆角（`LPRadius`）
| Token | 值 | 适用 | 不要 |
|---|---|---|---|
| `sm` | 6 | 输入框、小标签 | — |
| `md` | 8 | **卡片标准圆角** | 🚫 同屏卡片混用不同圆角 |
| `lg` | 12 | hero 卡、大容器 | — |
| `full` | 胶囊 | 标签、头像、分数胶囊 | 🚫 当卡片圆角 |

### 边框
- 标准：`1px solid border(#E5E5E5)`，用于卡片/输入框。
- ✅ 适用：所有白卡与输入框（这是当前层次的主要手段）。
- 🚫 不要：边框 + 阴影同时重用造成"双重描边"。

### 阴影（⚠️ 当前 app 没有，建议补充）
当前完全靠边框，偏扁平。建议引入轻量阶梯（可选，落地前确认）：

| Token | 值 | 适用 | 不要 |
|---|---|---|---|
| `shadow-none` | 无 | 默认（保持现有扁平） | — |
| `shadow-1` | `0 1px 3px rgba(10,10,10,0.06)` | 卡片轻微抬升（替代或叠加细边框） | 🚫 列表里每张卡都重阴影（噪音） |
| `shadow-2` | `0 4px 16px rgba(10,10,10,0.10)` | 浮层、sheet、弹出 | 🚫 当常规卡片 |

## 8. 核心组件规范

### 8.1 卡片 Card
- 规格：`card` 底 + `1px border` + `radius md(8)` + 内边距 `md(16)`（密集列表 12）。
- ✅ 适用：列表项、信息块、表单分组。
- 🚫 不要：嵌套卡片；内边距乱跳；同屏混圆角。

### 8.2 按钮 Button
| 类型 | 规格 | 适用 | 不要 |
|---|---|---|---|
| Primary | `accent` 实心 + 白字 + `radius sm/md` + 垂直 14 | 每屏唯一主操作 | 🚫 用黑色（修 §11.1）；🚫 一屏两个 |
| Secondary | 描边 / `accentSoft` 底 + 紫字 | 次级操作 | 🚫 与 Primary 同等视觉重量 |
| Text | 纯紫字 + 图标（`Label`） | 行内操作（跳转/刷新） | 🚫 当主操作 |
| 禁用态 | 透明度 0.5 + `.disabled` | 表单未填全 | — |

### 8.3 标签 / 胶囊 Pill
- 规格：胶囊 + `caption2/micro` + 内边距 `h7 v2`；语义底色（评分 soft / accentSoft）。
- ✅ 适用：评分小标签、状态标记（high→"重点"）、type 标记。
- 🚫 不要：超过 ~6 字；当按钮用。

### 8.4 头像 Avatar
- 规格：首字母 + 44×44 + `accentSoft` 底 + `accentText` 字 + 圆形。
- ✅ 适用：主播、用户。 🚫 不要：放真实图片时不裁圆；尺寸乱改。

### 8.5 评分展示 Score
- 数字：`display(44)` hero / `title-m(22)` 行内；颜色走 §4.4 阈值。
- 进度条：`bgSoft` 轨 + 语义色填充，高 6。
- 🤔 建议补充 `ScoreRing` 环形组件统一复用（场次/洞察/趋势）。
- 🚫 不要：分数无配色（光秃数字）；不同屏不同阈值。

### 8.6 列表行 Row
- 规格：卡片 + 左信息（标题 `body-strong` + 元信息 `caption`）+ 右动作（chevron / 分数）。
- 🚫 不要：右侧塞超过一个语义（分数 + chevron + 标签全堆）。

### 8.7 Tab 条
- 规格：等宽 + 选中 `accent` 字 + 2px 紫下划线，未选 `textMute`。
- 🚫 不要：超过 4–5 个 tab；图标+文字混排不齐。

## 9. 状态规范（建议统一为一个 `LPStateView`）

当前每屏各写各的（见 §11.7）。统一规范：

| 状态 | 规格 | 文案语气 | 不要 |
|---|---|---|---|
| 加载 Loading | 居中 `ProgressView` tint `accent` + 一行说明"加载…中" | 中性 | 🚫 只转圈不给文案（现状）；🚫 假进度 |
| 空 Empty | `textFaint` 图标 40 + `headline` 主文案 + `caption` 解释 + （可选）引导动作 | 教练、给下一步 | 🚫 当错误处理；🚫 空就报红 |
| 错误 Error | `textFaint` 图标 40 + `caption` 文案 + "重试"文字按钮 | 平和、可恢复 | 🚫 暴露技术细节/堆栈 |
| 未就绪 NotReady | hourglass 图标 + "分析进行中，完成后显示" | 安抚等待 | 🚫 当错误 |

- ✅ 适用：所有拉数据的屏。**全用同一组件，仅图标/文案变量化**。

## 10. 图标 / 插画 / 文案语气

### 图标
- 统一 **SF Symbols**，不混入自绘图标。空态图标 40pt `textFaint`，行内图标随字号。
- 常用映射：上传 `video.badge.plus`、跳转 `play.circle`、导出 `square.and.arrow.up`、趋势 `chart.xyaxis.line`、空态 `sparkles`、错误 `exclamationmark.triangle` / `wifi.exclamationmark`。
- 🚫 不要：同一动作在不同屏用不同图标；为装饰加无意义图标。

### 插画
- 当前无插画，靠图标 + 文案。保持克制；如引入，仅用于空态/引导，单色紫调。
- 🚫 不要：彩色卡通插画（与专业气质冲突）。

### 文案语气
- 中文为主；**鼓励 + 给下一步**；短标签（综合分/互动/转化/跳转/导出）。
- ✅ 空态举例（照抄现有调性）："本场暂无可分享高光 · 这场转化/互动信号较弱"、"上传一场录屏后会自动生成"。
- 🚫 不要："错误""无效""失败"当标题面孔；🚫 negative 洞察羞辱用户（ADR-0003）；🚫 英文术语直接抛给用户。
